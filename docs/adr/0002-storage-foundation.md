# ADR 0002: PostgreSQL metadata and immutable object storage

Status: accepted for the storage foundation; protected APIs and publication approval remain subsequent work.

Use PostgreSQL 18.6 for tenant-scoped metadata and `pg` 8.23.1 for transactions. Every transaction uses one checked-out client. Ordered SQL migrations run under a transaction and advisory lock; applied SHA-256 checksums are immutable. Artwork and exhibition snapshots reject updates and deletes. Composite tenant foreign keys prevent cross-tenant references. Mutable entities expose revision and timestamps; the artwork write method uses compare-and-swap and appends a snapshot. Other entities provide structural metadata foundations, not finished editor/lifecycle behavior.

Use content-addressed objects through the filesystem adapter or AWS S3 SDK 3.1144.0. Assets store keys, SHA-256, MIME, byte count, scale, rights references and processing state; PostgreSQL has no binary column. Maximum object size is 32 MiB in this foundation. Both adapters refuse conflicting replacement bytes. The S3 adapter uses `If-None-Match: *`; a 412 is accepted only after verifying identical existing bytes. Unsupported conditional writes fail integration and must not be silently downgraded. Production S3 compatibility, credentials, TLS, policies, quotas and operational deployment require separate qualification.

The local S3 test backend is Adobe S3Mock 5.2.3, an Apache-2.0 test server. It is not a production object store. MinIO's upstream repository was archived on April 25, 2026, so it was not selected as the maintained local reference. OCI multi-architecture index digests are pinned in `database/images.json` and Compose; PostgreSQL is under the PostgreSQL License. npm dependency licenses and original files remain in their packages. These server libraries are not included in the browser build. No hosted resource is created: new service charges are zero; local storage and Docker resources use the existing development machine.

Ingest first checks membership and artist ownership, then serializes a tenant-scoped idempotency key. Quarantine write precedes atomic metadata, immutable snapshot, request ledger and outbox inserts. A rollback leaves recoverable orphan bytes. The worker locks one due job with `FOR UPDATE SKIP LOCKED`, copies verified bytes to an immutable `stored` key and commits asset/job updates together. Failures retain a generic error, delay one second and stop after five attempts. A crash releases the transaction lock and allows a retry. `stored` means bytes were hash-checked, not format-validated, ready, licensed for publication or publicly accessible. Asset validation and authorization/session APIs are not introduced by this task.

All library writers acquire shared advisory lock 82002. Reconciliation and restoration acquire its exclusive form. Reconciliation defaults to detection; an admin applying it copies unreferenced quarantine/stored objects into a deterministic trash archive, verifies the copy, writes an immutable hash/size/path manifest, then removes the original. Trash has no automatic expiry. Restoration requires an admin actor and validates tenant scope and archive identity before an immutable put. This remains recoverable if metadata rollback follows a blob archive. Raw database/object-store administration must quiesce library workers and obey the maintenance protocol.

The filesystem root must be private to the service account with no hostile concurrent local writer. Path checks and `O_NOFOLLOW` reject traversal and symlinks; they do not replace OS directory ownership. File contents are fsynced before an atomic hard link. Directory fsync and power-loss durability are not claimed. PostgreSQL credentials are trusted internal infrastructure: membership checks protect library operations, while direct SQL access is privileged. This foundation does not provide row-level security, auth middleware, HTTP resource endpoints or a security boundary against a stolen database credential.
