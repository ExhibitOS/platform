# ADR 0003: Tenant-bound database sessions and server resource policy

Status: implementation candidate. This decision records the reference auth design; actual test results belong to the implementation handoff.

Use a database-backed password/session adapter for this development stage. Login selects an explicit tenant membership. Artist identity remains separate from login identity. Every protected request resolves the session and current membership on the server; an admin membership in one tenant does not grant access to another tenant. A local mode permits loopback HTTP for development but still authenticates every protected resource. A network mode requires an HTTPS configured origin and secure session cookies. Because the reference server is HTTP, network mode also requires a loopback bind behind an external TLS terminator; external plaintext listeners are rejected. There is no authentication-disabled mode.

Hash passwords with Node 24.21.0's asynchronous Argon2id API, a fresh 16-byte salt, 32-byte result, 19,456 KiB memory, two passes and one lane. Store the algorithm and parameters with the hash. These parameters follow the [OWASP password-storage recommendation](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html). The pinned [Node crypto documentation](https://nodejs.org/download/release/v24.21.0/docs/api/crypto.html#cryptoargon2algorithm-parameters-callback) describes the API. The pinned runtime and verification fixtures control compatibility with this API, introduced in Node 24.7.0. No shared default password, committed secret, hosted identity subscription or opaque private dependency is required.

Issue an opaque random session bearer in a host-only HttpOnly cookie. Store its SHA-256 hash in PostgreSQL; never return the bearer in JSON. Session expiry, revoked state, disabled user state and tenant membership are checked on requests. The CSRF token is a separate random value exposed through the authenticated session response, with its corresponding hash stored for comparison. It is not a session bearer. Request logs must exclude passwords, cookies, CSRF headers and authorization values. HTTP responses do not expose database error details or password/session hashes.

Use explicit same-origin checks plus a synchronizer token on authenticated state-changing requests. Cookies' SameSite setting adds a browser safeguard but does not replace that token. Login requires the configured Origin before a session exists. Host validation and disabled proxy trust prevent forwarded headers from turning a local configuration into a network bypass. These controls follow the [OWASP session guide](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html) and [CSRF guide](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html). Deployment must separately provide TLS and a correctly configured proxy; accepting an HTTPS origin string does not itself install TLS.

Resource policy joins ownership and assignments inside tenant-scoped SQL transactions. Changes to membership, assignments, sessions and disabled status take an exclusive advisory lock; checked resource operations retain its shared form until their transaction ends. Revocation thus takes effect after already-authorized in-flight work completes. Artwork/exhibition edits use an expected revision and append immutable snapshots. A stale revision fails rather than overwriting another edit.

Bootstrap is an operator CLI, not an anonymous HTTP endpoint. It reads a bounded secret from stdin and creates the initial tenant admin in a transaction only once. It does not place the secret in argv, logs, a shared password or a fixture. Credential recovery and extra account enrollment are privileged operational work, not a public signup or password-reset flow in this stage.

Use the pinned public `@exhibitos/spec/schemas/artwork.json` export and its `$defs.rights` schema for the full OES rights shape, rather than introducing a parallel flat permission representation. Export eligibility validates the schema with AJV and checks the current UTC validity interval and requires nested `permissions.export`. Private bytes delivery validates the same schema and checks nested `permissions.download` and the current validity interval, then checks storage state/hash/size. These permission flags are independent of each other and of `display`. Malformed or legacy flat records fail closed; compatibility does not silently widen an existing grant. This public dependency is server-side and is not added to the browser bundle. Its artifact provenance remains in [artifact.json](../../contracts/artifact.json).

[Auth usage and policy](../auth.md) and the [OpenAPI contract](../../contracts/auth-openapi.json) document the implemented surface. External OIDC integration, MFA, email verification, password recovery, signed object URLs, real OEX byte export and an anonymous publication endpoint are not provided by this decision. Export-check reports eligibility for a future export, not a delivered archive or file URL. Browser content sanitization, rendering validation and upload security remain separate requirements.

Primary sources verified October 1, 2026: the links above, [Fastify server options](https://fastify.dev/docs/latest/Reference/Server/) and [OpenAPI 3.1.1](https://spec.openapis.org/oas/v3.1.1.html). This decision does not claim a penetration test, production certification or completed external identity adapter.
