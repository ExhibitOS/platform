# ADR0004: Reviewed CMS revisions and private display derivatives

Status: candidate; actual checks are recorded in [T02-04 evidence](../evidence/T02-04.md).

Keep artist identity separate from authentication. Tenant-scoped owning artist/admin mutations create immutable revision snapshots and use expected-revision CAS. Archive and restore retain source bytes/history. A new durable `cms_managed` column enforces validated CMS edits and the full governing artwork rights ceiling independently of whether metadata is currently valid. Legacy generic PATCH cannot remove this ceiling; assigned display readers use a whitelisted projection rather than legacy private metadata. Existing non-CMS storage records keep their prior API policy. Applied migrations001–004 are unchanged;005 backfills the current legacy artist snapshot without inventing past history.

The CMS form is a structured metadata record, not a complete exported OES artifact. Dimensions remain positive meters; original units and already-applied scale conversion are explicit provenance, without automatic geometry rescaling. Full rights reuse the pinned public OES schema. Reviewer approval binds current immutable artwork revision, selected format-approved asset and rights revision/hash. Any metadata mutation invalidates current approval. Import-format approval and reviewed CMS approval are distinct from publication.

Use separate server-generated display copies. PNG strips all unsupported metadata and creates a bounded striped image without altering originals. The first GLB watermark profile accepts static identity-node geometry only, rejects deformation/animations/unreachable data, uses POSITION bounds and counts scene-expanded vertices/index entries/draw calls including mesh reuse. It adds red watermark geometry, while retaining original mesh data: removal/copying remains possible and DRM is not claimed. This restricted profile is explicit in the UI and [usage guide](../cms.md); future support must compute transformed/deformed bounds rather than weakening checks.

Session/resource access and current display rights are checked before any bytes. Assigned viewers need an explicit can-view exhibition relationship; curators follow assigned-exhibition access. Original download and export remain owning-artist/admin operations requiring the intersection of current artwork and per-asset rights, with independent permission flags and time intervals. Missing/malformed managed rights fail closed. No anonymous publication endpoint or OEX generation is added.

Reuse the bounded isolated validation worker for derivatives. Keep immutable derivative records with source hash and display policy, retain maintenance references, and include new history/approval/import/derivative tables in synthetic backup restore equality checks. No automatic deletion or hosted resource is introduced. Three.js is loaded only for preview; preserve its original MIT notice in the production notices artifact. Large renderer chunk warning is documented rather than treated as a proven performance budget.
