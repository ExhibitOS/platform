# Artist CMS reference flow

Candidate implementation: actual acceptance evidence is recorded before merge. The [CMS OpenAPI contract](../contracts/cms-openapi.json) describes protected routes. Open `/cms` on the same origin as the authenticated API. The page uses server session cookies and CSRF tokens, never a client-supplied role. Login identity and artist identity have independent IDs; an artist can create an identity linked only to their own login, while a tenant admin can create an unlinked identity or explicitly link an existing tenant member. Login enrollment remains the protected admin flow described in [auth.md](auth.md).

Create an artist profile, then an artwork with title/plain text description, positive width/height/depth in meters, the full public OES rights record, and authorship/source-unit/scale-conversion notes. These fields are reviewed metadata, not a complete exported OES artifact. They do not rescale geometry automatically. Record an already-applied conversion accurately; no second transform is silently added. Code licensing does not grant rights in uploaded artwork.

Upload an eligible GLB or PNG through the [existing staged import](imports.md). Import `approved` means file-format approval only. CMS review separately binds the current artwork revision, dimensions, rights/provenance and selected approved asset hash/size/MIME/rights revision to an immutable approval snapshot. A metadata edit appends an immutable revision, revokes current review approval and updates the current rights governing original assets. Review the new revision again. Stale edits return `REVISION_CONFLICT` and must not overwrite another revision. Repeating the same review is idempotent; selecting different bytes under the same reviewed revision conflicts.

Artist/artwork lists use tenant-scoped UUID keyset cursors, literal title/name substring filters and at most50 entries per request. Private details omit object paths, secrets and operational import internals; invalid legacy artwork metadata is returned as null for explicit correction rather than blindly exposing arbitrary fields. Artist and artwork histories are immutable snapshots, bounded to the most recent100 per response. Artist name/bio are plain text rendered through React escaping. Archive and restore append revisions and retain bytes/history; an active artwork prevents archiving its artist. No actual artwork data is automatically deleted.

## Preview and rights

A reviewed artwork's preview endpoint delivers a separately generated display copy only after current tenant/resource access and independent full-schema `permissions.display` plus the current UTC interval pass. A viewer can view a derivative only through an explicitly readable assigned exhibition containing that artwork. Curators use their existing assigned-exhibition policy. These readers cannot gain artist edit, original-download or export permissions. The safe display serializer permits title/description/artist name/physical dimensions/credit line and eligible flags; it omits private provenance notes, login IDs, storage keys and full rights records. There is no anonymous publication endpoint in this task.

A durable `cms_managed` flag prevents deleting the governing rights through the legacy generic metadata route: that route returns `CMS_ROUTE_REQUIRED`. Legacy private metadata reads of managed artworks are limited to owner/admin; assigned display readers use the safe projection. Malformed or missing managed rights fail closed. Original delivery separately requires `permissions.download`; export eligibility separately requires `permissions.export`. A display-only artwork therefore denies both original and export endpoints while allowing its permitted display copy. Export-check does not generate an OEX package. Rights expiry, revision edits, archive or assignment revocation take effect on subsequent protected requests.

PNG display copies have at most512-pixel width and opaque diagonal red watermark stripes; the original bytes remain unchanged. GLB display copies add explicit red stripe geometry across qualified model POSITION bounds and retain the original mesh geometry. This is a visible attribution/access-policy tool, not cryptographic DRM. A browser receives display bytes; users can copy them and remove marks. The UI makes this limit explicit.

The initial GLB CMS review profile is narrower than the importer: one default scene, all nodes/meshes reachable, static geometry, identity node matrices/TRS, and no animations, skins, morph targets or weights. Scene-expanded limits are500,000 POSITION vertices,1,500,000 index entries and256 primitive draw calls, counting repeated mesh instances. Bounds use mesh POSITION accessors, not normals. Unsupported transforms/deformations fail derivative generation and cannot receive a reviewed CMS revision. Bake transforms before import in a trusted authoring tool and document the conversion. General animated/transformed-model watermarking is not implemented. Texture/image/extension/URI restrictions remain those of the importer. PNG remains non-interlaced8-bitRGB/RGBA without ancillary chunks.

Decoder/derivative subprocesses enforce five-second timeout,128MiB JS heap, bounded input/PNG expansion/depth/output. These are not a total OS RSS sandbox. Generated immutable derivative keys are retained with asset references and included by database/object backup inventory; Git backups do not contain any artwork bytes or job/approval rows. Use the consistent recovery process in [storage.md](storage.md). No hosted provider or paid service is created.
