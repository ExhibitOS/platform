# T02-02 authentication and tenant policy evidence

Candidate implementation; root independent review and merge remain required.
Date: 2026-10-01. Host: macOS 26.2 arm64; Node 24.21.0, npm 11.19.0.
All users, tenants, passwords and bytes in tests are synthetic, in UUID-named
Docker resources which are label-checked before cleanup. No paid service created.

Implemented PostgreSQL-backed opaque sessions, Argon2id passwords, one-time
transactional stdin bootstrap, CSRF/Host/Origin checks, explicit curator/viewer
assignments, artist ownership, tenant-scoped administration, immediate revoke,
last-admin protection, metadata revision compare-and-swap, private asset metadata
and download authorization. Public OES rights schema validates nested permissions
and strict UTC/calendar/time bounds. Export-check returns authorization only.
The API binds loopback, including network mode; network operation requires an
external TLS terminator with configured exact HTTPS origin and unchanged Host.

Actual checks:
- npm ci and npm run check: typecheck/lint, 14 unit tests, build, 8 public
  contract consumer tests PASS.
- node scripts/test-storage.mjs: actual pinned PostgreSQL/S3Mock fresh/forward/no-op
  migrations, immutable storage, transactions/retry, orphan archive/restore,
  pg_dump/pg_restore and 7 blob hashes, S3Mock restart PASS after auth migration.
- npm run test:auth: 18 integration groups PASS, actual isolated PostgreSQL,
  HTTP injection, startup rejection, bounded concurrency and real ephemeral HTTP
  Chromium HttpOnly/SameSite/login/session/CSRF/logout checks. All clients have
  5-second PostgreSQL statement timeout; concurrency check has 7-second watchdog.
- npm run test:e2e: existing 3 Chromium foundation scenarios PASS. A strip-only
  parameter-property regression was corrected using plain fields/assignments;
  plain-field source execution was restored; final root Chromium rerun is recorded before merge.

Acceptance coverage in scripts/test-auth.mjs: cross-tenant read/write/exhibition/
asset/export denial; denied requests do not read blob bytes; own-artist bytes
match actual hash/size; download/export/display grants independent; malformed
rights/calendar/leap-second and expired grants denied; CSRF/foreign Host/Origin/
forwarded identity/extra body keys rejected; logout/revoke/disable/membership/
assignment/expiry deny stale cookies; one concurrent bootstrap succeeds;
maintenance and resource writes share one lock order; backup blocks login writes;
unknown user and wrong password produce same status/code and use Argon2id; login
rate/KDF concurrency bounded. This does not claim timing indistinguishability.

Limits: no OIDC/MFA/password recovery, anonymous publication, GLB/image decoder
approval, real OEX package delivery, signed URLs or production TLS configuration.
Cookie lifecycle was checked in local Chromium, not all browser/OS combinations.
No JWT or external identity subscription. Direct SQL remains privileged and
must obey documented maintenance locking. SQL migrations 001/002 are unchanged;
003 is additive. Auth/session audit writes are covered by maintenance locks.

Rollback: stop API before restore; preserve a quiesced DB/object backup, deploy
previous application in a separate environment and restore there. Do not delete
credentials or alter applied migration checksums. Keep existing immutable
snapshot/public artifact identities and rights licenses unchanged.
