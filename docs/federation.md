# Public exhibition discovery protocol v1

Federation is an optional directory, independent of local publication and viewing. Operators explicitly opt individual public publications into discovery and pin an Ed25519 peer key before synchronization. Blocking a peer removes its cached directory entries; it does not withdraw or modify that peer's own exhibition. Peer keys cannot silently rotate. Identity changes require an operator decision and a separate preserved trust history.

`GET /api/v1/federation/discovery` returns `{payload,signature}`. Payload is the exact UTF-8 JSON string signed with Ed25519; signature is lowercase hexadecimal. Its closed schema contains version 1, the HTTPS origin, DER SPKI public key in base64, durable increasing sequence, canonical issued/expiry timestamps and at most 200 entries. Each entry has only `publicationId`, public `title`, same-origin `/p/<publicationId>` URL, `revisionSha256` and `publishedAt`. Original models, audio, artwork rights records, author accounts, tenant IDs, private drafts and deployment credentials are never synchronized. Discovery does not authorize downloading model bytes.

Generation rechecks current publication rights and availability under the same publication policy locks before signing. Only explicitly opted-in IDs enter the callback; withdrawal or rights expiry removes their entries from the next full snapshot. Receivers accept only pinned identities and strictly increasing valid sequences, then atomically replace that peer's full directory. Missing entries therefore propagate withdrawal without a tombstone history containing private metadata. Snapshots expire within one hour. Unreachable peers preserve the last verified cache with an explicit stale marker; no cached entry is a guarantee that its original public URL is still available. Local viewing never depends on this cache or on any central server.

Production synchronization permits only exact public HTTPS origins. Every resolved address must be globally routable; the TLS request is pinned to the checked address and still verifies the original hostname. Redirects, local/private/link-local/mapped networks and remote viewer URLs are refused. DNS and response deadlines, a 256 KiB response limit, 64-peer/200-entry limits and a persisted one-minute per-peer sync interval bound requests and cache growth. Protected administration uses the existing admin role and CSRF/origin checks; discovery HTTP requests also require the existing rate limiter. Concurrent block/moderation changes are rechecked before committing a fetched snapshot.

Migration 012 adds persistent opt-ins, identity sequence, peer trust/block state and directory cache. Signing keys remain operator configuration in the existing secret mechanism, never SQL rows, logs, OED or archives. A failed network sync records a bounded code and preserves old verified entries. Invalid identity/signature/schema/replay fails explicitly instead of accepting a cached snapshot as fresh.

The dedicated two-server scenario uses actual HTTP listeners and independent PostgreSQL namespaces with synthetic publications. Its injectable transport maps synthetic public origins to those listeners for test isolation only; production routes never accept a transport, URL override or verification flag from IPC/HTTP. This test does not claim public Internet TLS or external VPS qualification. Actual scenario results must be recorded separately; source-only implementation is not a completed T12-02 acceptance.
