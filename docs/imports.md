# Authenticated primary-asset imports

## Bounded model preparation worker

`prepareCompactModelInWorker(originalBytes, {bytes, sha256}, hooks)` is the shared producer seam for `embedded-model-compact-20k-512-v1`. The identity comes from a durable authenticated import job, never an asset-specific source allowlist. The ordinary import hook below uses this seam; it does not confer publication approval. Required preparation intent and durable job integration remain separate from the existing optional `model-texture-pair` behavior below.

The bounded subset is a static, self-contained GLB with one identity node, one indexed triangle primitive and material, Float32 position/normal/UV streams, and embedded RGB base colour plus optional distinct normal and grayscale/RGB occlusion images. It accepts bounded baseline eight-bit JPEG or PNG through the isolated product decoder. No external resources, extensions, animation, transforms, ICC profiles, alpha, inferred units or physical rescaling are accepted by this recipe. The source is limited to 32 MiB, 131,072 vertices, 200,000 triangles and three images of at most 4,096 × 4,096 pixels, with 16 MiB aggregate compressed image bytes. A source outside this subset remains unsupported; this does not change the ordinary decoder's admission.

Compatible compact PNG originals remain byte-identical after actual decode and strict ordinary GLB validation. Otherwise the worker produces at most 20,000 triangles and 512-pixel textures, preserving material roles, UVs and source coordinates. Simplification retains source vertex attributes and locks axis extrema; it rejects unmet triangle/error/bounds constraints. Colour averaging uses linear-light sRGB, occlusion uses its linear channel, and normal averaging renormalizes vectors. Output is RGB PNG inside a GLB, at most 8 MiB. It is a generated display derivative, never an original or proof of visual equivalence.

The worker pins the packaged meshoptimizer 1.1.1 and sharp 0.35.4/vips 8.18.6/mozjpeg 0826579 dependencies. It processes image entropy sequentially, has a 256 MiB JavaScript heap and a 20-second wall deadline, and then invokes the unchanged strict GLB validator. Heap size is not an OS memory cap. Results include measured source/output hashes and sizes, geometry/bounds, per-role input/decode/output hashes, recipe digest and resource usage. Private paths and rights are not inferred. The caller retains original custody and independently checks current authorization/rights before committing any result.

The promise settles only after both child `close` events. Optional `writerFd` must be a live caller-owned native writer descriptor; it is inherited by preparation and validation. `AbortSignal` kills the current owned child and still awaits close. A private parent pipe terminates an orphan preparation worker. `MODEL_PREPARATION_*` failures never return a usable result; callers must retain the original and must not present required failed preparation as ready for review. A successful worker result remains distinct from explicit artwork approval, save/reopen, export and actual Viewer use.


## Required compact preparation on ordinary imports

The separately selected catalog 045 supplement adds `model_preparation` to the existing import job; the base 25 migrations and existing 044 payload remain unchanged. It preserves optional 022 texture-pair semantics and image preparation. Capability advertisement, create and claim use one execution predicate: selected schema, bounded blob reader and active importer. Native execution additionally requires the authenticated issued writer lease, matching workspace/principal and live physical owner. The native entry shares this execution context between HTTP and the background importer. An unconfigured or stopped importer does not accept or claim required model jobs; neither HTTP fields nor a raw environment descriptor establish authority. Isolated service execution must be selected explicitly by trusted application code and cannot be substituted for a native workspace context.

Add this closed optional field to the ordinary `POST /api/v1/tenants/:tenantId/imports` body:

```json
{
  "modelPreparation": {
    "version": 1,
    "profileId": "embedded-model-compact-20k-512-v1",
    "operationID": "same-as-idempotencyKey",
    "generation": "durably-saved-transfer-generation",
    "artworkRevision": 1
  }
}
```

`operationID` and `generation` use the existing 1–128 character `[A-Za-z0-9][A-Za-z0-9._-]*` token grammar. The operation equals the existing idempotency key. `artworkRevision` is the current mutable draft revision, including a newly created artwork at revision 1; no previous approval is required. This field is exclusive with `modelDerivation`, `coarsePreparation` and client-declared `derived`. It uses the existing GLB MIME, declared original hash/size, rights and scale fields. The recipe preserves source coordinates; declared scale/physical dimensions still come from the author. A provisional imported-demo replacement is a separate operation and is not admitted by this hook.

The existing `PUT .../:jobId/bytes`, `POST .../:jobId/complete`, `GET .../:jobId`, retry and cancellation endpoints remain unchanged. Persist the intent/idempotency key before the first POST and the job ID before upload. Identical replay returns the same job; changed replay conflicts. Completion queues automatic shared preparation, validates the generated display using the ordinary decoder, rechecks owner/rights/revision and atomically records the original, display and lineage. Required preparation failure preserves the uploaded original and commits no display asset. The worker never falls back to approving an unsupported original. Compatible supported originals retain exact bytes and use one asset ID for both original and display.

Every required-profile response contains flattened intent fields plus `required: true`, `status` (`pending`, `processing`, `ready`, `failed`, `cancelled`), `workerDrained` and `original: {mime, sha256, bytes}`. Before ready it omits top-level `assetId`, `original.assetId`, `display` and `serverReceipt`. Ready adds committed `original.assetId`, `display: {assetId, mime, sha256, bytes, reusedOriginal}` and the typed `serverReceipt`; display ID equals the top-level asset ID. Equal original/display IDs are allowed only for exact reused bytes/hash. Generated displays have distinct IDs and private original custody. Even an internally committed `approved` import row remains `processing` without usable output identity until all actual worker tokens have drained. That import state is separate from the existing explicit CMS artwork approval.

`ModelPreparationServerReceipt` in `model-preparation-intent.ts` is the authoritative typed wire: version/profile/recipe digest, job/artwork/current revision, operation/generation, rights digest, original/display bindings, typed producer metrics and a canonical SHA-256. The server reconstructs and verifies it against the authoritative job plus committed assets/rights/lineage on ready reads, approved idempotent POST replay and explicit approval. Clients decode semantic fields and retain the digest for correlation; they must not claim independent digest verification by reserializing floating-point JSON. No private paths or physical writer identifiers appear in this receipt.

`INVALID_MODEL_PREPARATION`, `MODEL_PREPARATION_CONTEXT_CHANGED`, `MODEL_PREPARATION_RECEIPT_INVALID`, safe `MODEL_PREPARATION_*` worker errors and `WORKER_DRAIN_UNCONFIRMED` distinguish malformed intent, changed authority/content, invalid evidence, unsupported generation and an unresolved worker. Existing `errorCode` and `retryAt` remain authoritative. Retry uses the same retained input/job only after the existing backoff and actual drain checks. Current rights and revision are rechecked before explicit CMS approval, which remains a separate user action.

Normal native close already awaits the running import and both child processes before returning its owner lease; queued/failed input and committed receipts survive reopen. An unclean process loss with an unresolved invocation token stays closed/uncertain. There is no timeout-based drain claim, PID-only recovery, automatic lease takeover or generic historical migration. A supported native app-closed proof is required before any future narrow recovery can clear such a token. This source operation does not itself qualify a Manager package, live profile transition, save/export, public display or visual equivalence.

Each current artwork revision reserves one required intake through preparation and explicit review. A different new operation receives `409 MODEL_PREPARATION_ACTIVE_IMPORT` before upload while that reservation is active or undrained. Idempotent replay remains available. A drained failed or cancelled job releases the slot; retry reacquires it and cannot reactivate alongside a replacement. A different CMS asset cannot bypass the reserved review. Originals, receipts and approval history stay retained. After a ready candidate, finish its review or use the existing revise flow for a new draft; this change does not add ready-candidate deletion.

New required-preparation jobs serialize against CMS approval on the current artwork row. A valid idempotent replay remains available after approval; a new job for the already-approved current revision returns `409 MODEL_PREPARATION_REVISION_APPROVED` without creating custody. Use the existing revise flow for a new draft. The exact reserved Hayes input (`e66715a51c9cad0b904d2715d5b27fb80b97d43fe8c2a3cd10276c1b336a2cf6`, 8,383,096 bytes) currently requires its dedicated owner route and returns `409 MODEL_PREPARATION_DEDICATED_ROUTE_REQUIRED` on new required intake. This is a current routing restriction, not a decoder failure; other supported inputs are not source-hash allowlisted.

The native selected supplement is `database/native-model-preparation/045_required_model_preparation.sql`, SHA-256 `ebd546db086b5488374abae719f34f0c18de95c9a6eb74acd69e2cea6f6430d8`. Its exact `native-model-preparation-capability-v1.json` marker is exported by `MODEL_PREPARATION_CAPABILITY`. An occupied 044 workspace requires the distinct authenticated `workspace-furnishing-044-to-045-upgrade-v1` mode (lease MAC byte 8) and `catalog-upgrade-044-to-045` admission (byte 6). Existing values remain unchanged. Ordinary reopen never applies this supplement; the directed edge verifies the exact 044 ledger and current owner before applying only 045 in the existing transaction. Manager must bind the reviewed source/target payloads and preserve its current owner checkpoint before invoking it. Source support alone does not prove that transition or a particular packaged target.

The existing native packager accepts explicit `modelPreparationSelected: true` only with the ordinary non-probe 044/Hayes-release prerequisites and private editor. It verifies the existing 044 parent marker, copies the exact selected 045 SQL and emits its exact marker. Omitting this option keeps both selected files absent. This source option is not a sealed target or Manager admission proof; the eventual integrated source, configuration and payload manifest must be qualified before `Upgrade44`.

Service inventory retains the original with its source hash/size and records the approved display key with the receipt's display hash/size. Unresolved worker tokens remain an explicit drain issue. Clean close/restart can preserve and resume queued work; an unconfirmed crashed invocation remains closed/uncertain and is not reclaimed using age or PID absence.


## Original lineage for an already registered frame

The native owner session advertises `workspaceRegisteredFrameLineageProfile: "registered-frame-original-lineage-v1"` only with the existing issued furnishing writer and frame-preparation capability. This narrow operation requires catalog 041 and one of the three existing `omit-unused-invalid-tangent-r1` source/renderable pairs. It preserves the registered furnishing ID/version, descriptor, rights, provenance, request hash, received bytes and object key. It records a **new actual preparation in this owner**, not a claim that the historical registration used an original. It is separate from ordinary intake replay, publication and default-catalog inclusion.

All paths below use the existing authenticated owner session and mutating-request CSRF handling. Let `L` be `/api/v1/tenants/:tenantId/workspace/furnishing-intakes/:intakeId/original-lineage`.

1. `POST L` stages the existing immutable 041 binding. Body: `{requestId, furnishingId, furnishingVersion:1, sourceModel:{mime:"model/gltf-binary",bytes,sha256}, recipe:"omit-unused-invalid-tangent-r1"}`. IDs must match the existing historical registration; source bytes/hash must match its pinned acquired original. Changed replay conflicts. No descriptor or intake is rewritten.
2. `PUT L/model` with `Content-Type: application/octet-stream` durably uploads the exact original (maximum 177,500 bytes). Retry accepts the identical original without duplicate storage or registration.
3. `POST L/complete` with `{}` runs the existing bounded frame worker and strict GLB validator, both holding the writer FD until actual child close. Only an exact match to the existing renderable, unchanged owner/input/rights and successful worker drain can append the immutable registered lineage. Concurrent completion serializes on the existing owner intake row and returns the same receipt.
4. `GET L` is the durable continuation entry after lost response, process restart or reopen. Its phases are `not-started`, `awaiting-original`, `ready-to-prepare`, and `registered`. A `complete` request is synchronous and bounded; there is no persisted `processing` claim. A concurrent read waits for that transaction, then observes its committed result or the retained retryable stage. `registered` alone includes `workerDrained:true` and a receipt with workspace/intake/recipe/source and renderable hashes. This does not attest Manager's later normal resource return.
5. `POST L/cancel` with `{}` deletes only the staged original and staging row. It never removes or edits the existing renderable. An interrupted deletion can be retried. Registered lineage cannot be canceled or overwritten. Cancellation behind a successful concurrent completion returns `JOB_STATE`.

Every response also binds version/kind, owner IDs, historical request ID and SHA256, furnishing ID/version, exact source/renderable model declarations and canonical descriptor SHA256. Clients must use this endpoint for lineage status; the historical intake's `registered` phase still means its original direct registration. Missing originals, changed renderables, wrong owners, changed bindings and unsupported rights fail closed. A failed completion retains the stage for the same `complete` retry; it does not re-import, re-register or replace the furnishing. Existing inventory refuses an unsettled stage, and after settlement retains and verifies both objects. No implicit catalog transition or historical compatibility is provided by these routes.

## Same-owner reviewed image replacement

In a qualified native workspace, an owning user can prepare a reviewed image pair for an existing artwork. Create the normal JPEG import with `derived` containing the prepared PNG declaration and `coarsePreparation` containing only `{version:1, profile:"viewer-png-box-512-v1", approvalId, artworkRevision}`. Supply the original JPEG to `PUT .../bytes`, its declared PNG to `PUT .../derived-bytes`, and complete the job. The server admits only the exact original, prepared PNG, recipe and rights of an existing reviewed policy entry; it generates and verifies the coarse PNG. The ICC preparation recipe remains **client-declared**, not independently certified by the server. The client does not choose coarse asset IDs, keys or hashes.

Poll the job until `state` is `approved`, `coarsePreparation.status` is `ready`, and `coarsePreparation.workerDrained` is `true`. Cancellation is not proof that a worker has stopped. A failed job can be retried only after its worker has drained and its retry time has passed. A process lost with an unconfirmed durable worker token remains blocked pending independently established recovery; expiry alone does not certify drain. Reconciliation refuses to run while such a job is undrained or its retained inventory is invalid.

With the current draft ETag, call `POST /api/v1/tenants/:tenantId/studio/exhibitions/:id/native-artwork-replacement` with `If-Match` and JSON `{requestId, artworkId, artworkRevision, importJobId}`. The native workspace owner, live database, current artwork revision, rights, job, original and both derived assets are rechecked. Success appends an immutable artwork approval and updates the selected artwork, matching placements and an entrance cover bound to its old primary in one transaction; unsupported old references fail closed. It returns the normal Studio response and ETag. Identical request replay returns its historical receipt; changed use of the request ID conflicts. A stale ETag or any failed validation leaves the prior artwork approval and draft intact. Existing published snapshots are not edited. Export, publication and runtime admission remain separate operations.

Implementation candidate; actual acceptance results are recorded before merge. This API adds one primary GLB or PNG asset to an existing artwork. It does not import an entire OES directory, OEX archive, JPEG/WebP, remote URL, or Capture dataset. Artwork metadata/dimensions/declared provenance are managed in [CMS](cms.md); exhibition composition, OEX export and publication are separate Studio operations. It accepts the public OES rights record and a positive physical `scaleMeters` value. Read [authentication](auth.md), [storage recovery](storage.md), and [OpenAPI](../contracts/import-openapi.json).

## Producer-independent GLB artwork flow

The 2026-10-21 product role is GLB-only handoff: optional Mac Processing handles CaptureSpike captures and saves reviewed GLB; Studio creates artworks from supported GLB produced by any tool. CaptureSpike/Processing installation, their accounts/signatures, OES folders, metadata sidecars and private capture histories are not prerequisites. Current CMS creates the artist/artwork record before this asset upload; a file-first UI transition is not claimed complete. Enter title, artist, measured dimensions, rights and declared source in CMS. User-declared provenance is not authenticated capture history, and geometry bounds are not verified physical measurements.

Reuse this authenticated upload rather than adding a new package receiver. Self-hosted accounts/DB/storage are sufficient; private Capture repositories or an ExhibitOS-operated central service are not required. Existing format/security limits still apply, so producer neutrality does not mean every GLB feature is accepted.

## Flow and authorization

An admin of the same tenant or the artwork's owning artist may create/read/upload/complete/cancel/retry its imports. Curator/viewer membership does not grant these operations. Every write needs the tenant-bound session cookie, exact Origin/Host and CSRF token from the auth session. A session or membership change is rechecked on requests, and the worker rechecks the submitter's current artwork ownership before approval. User input never selects an object path.

1. `POST /api/v1/tenants/:tenantId/imports`: send `artworkId`, `idempotencyKey` (1–128 characters), `mime`, lower-case `sha256`, expected `bytes` (1–32 MiB), `scaleMeters` (positive, at most 1,000,000), and full `rights`. Same tenant/key/canonical payload returns the same job; changed payload conflicts.
2. `PUT .../imports/:id/bytes`: send the complete object with exact `Content-Type: application/octet-stream`. Length/hash must match the declared values. Interrupted, missing or mismatched bytes never complete a job. Successful identical replay while uploading is safe.
3. `POST .../imports/:id/complete`: verify uploaded bytes and queue validation. Repeating completion for queued/processing/approved returns current state.
4. Poll `GET .../imports/:id`. State is `uploading → queued → processing → approved`, or `failed/cancelled`. Progress is a state milestone, not measured transfer percentage. An approved job returns its asset ID.
5. Failed jobs expose `retryAt` and require explicit retry after the recorded exponential delay; at most five attempts. Cancel fences a queued/processing worker with its lease identity. Approved jobs cannot be cancelled through this endpoint.

The standalone `import:work` entry is one-shot: after `npm run build`, supply private `DATABASE_URL` and `BLOB_ROOT` environment values and run `npm run import:work`. Repeat under a supervised scheduler when using that entry. The bundled local runtime already drives this worker automatically; do not start a duplicate worker for a normal local-runtime import. Never pass credentials in arguments or commit local data. The worker claims durable PostgreSQL jobs with a 30-second lease, runs a bounded decoder, then commits asset/rights/job together. Expired leases may be reclaimed; stale or cancelled workers cannot commit approval. No source or user bytes are automatically deleted.

## Qualified formats and limits

The platform limit is 32 MiB per object, narrower than the general public spec limit. GLB must be version 2 and self-contained. Untextured assets remain supported. An additional narrow profile accepts embedded base-colour PNG textures: exactly JSON and BIN chunks, one local buffer, at most sixteen embedded images across eight texture bindings, aggregate 2,097,152 pixels and 8 MiB compressed image bytes, dimensions at most 2,048, finite FLOAT UV coordinates in [0,1], and LINEAR samplers without mipmaps (CLAMP_TO_EDGE, REPEAT or MIRRORED_REPEAT). Image declarations are summed before any PNG inflation. Separate bounded PNG normal/AO maps are also supported as described below. JPEG, external resources, animation, skinning and unsupported channels are refused; the existing separately qualified sRGB Basis profile remains available for base colour. Existing PNG CRC/filter/bounded-inflation checks precede isolated Khronos validation. PNG must be non-interlaced, 8-bit RGB/RGBA, at most 4,194,304 pixels with dimensions no larger than 8,192, and at most 256 chunks. The conservative profile rejects ancillary metadata. CRC, complete chunk structure, compressed-stream length, bounded expansion and every scanline filter are validated; signature alone is insufficient.

The decoder has a five-second timeout, 128 MiB JavaScript heap limit and bounded output. Input/pixel/expanded-byte limits also bound native buffers; the heap flag alone is not a total OS memory sandbox. Failure terminates decoding and leaves quarantine unapproved. MIME spoof, truncated files, remote URI, malformed GLB/PNG and unsupported formats fail with safe errors; no external URL is fetched.

`approved` means this narrow import profile passed, not that rights permit publication or every renderer/browser/device is supported. A private original download still checks independent `permissions.download`, current rights validity, tenant/ownership and hash/size. There is no anonymous or public import-bytes route. This asset-import endpoint does not generate OEX, display derivatives or publications; those are separate [CMS](cms.md), [OEX](oex.md) and Studio operations.

## Recovery and retention

Quarantine and approved copies use immutable keys. Durable job references protect in-flight bytes from orphan reconciliation. A copy that succeeds before a database failure remains recoverable; retry cannot create a duplicate asset. Cancellation invalidates the lease but retains bytes. Trash, jobs and staging are not automatically purged; retention and actual data deletion need a separately verified recovery policy. Git backups exclude job rows, object bytes and credentials. Follow the consistent database/object backup procedure before introducing persistent artwork data.

Embedded images in the three local GLB previews are decoded from validated bounded image views through model-local loading handlers. The model cannot provide general blob, data, file or HTTP resources. Watermark display copies preserve embedded image bytes/views; texture assets retain their full variant when coarse generation reports `COARSE_UNAVAILABLE`. This profile does not qualify automatic multi-asset publication, texture reconstruction accuracy, physical calibration, or a new LOD algorithm.


### Mac textured output compatibility

The bounded embedded profile also accepts separate PNG normal and occlusion maps (unit scale/strength, UV set zero), with finite validated normal/tangent streams. LINEAR samplers may use CLAMP_TO_EDGE, REPEAT or MIRRORED_REPEAT. The existing aggregate pixel/byte limits and isolated decoder remain in force. Normal/AO maps must use distinct PNG image sources from base colour; sRGB Basis textures are not linear-map inputs. Ancillary metadata remains refused, so older files require an explicit compatible derivative rather than silent import changes. This is format compatibility, not physical quality or publication approval. Existing server membership, rights and lease checks are unchanged.


Optional `modelDerivation` uses `exhibitos-near-texture-pair-v1` on the existing import job (schema022). Its exact settings bytes are `{"allowSpatialSampling":true,"profileId":"exhibitos-near-texture-pair-v1"}` with SHA256 `da9039b67435883255f723fd3b37b0fc395ba2acce3ab26706aeaa17d90f73bf`; the public tool version is `public-near-texture-v1`. This route is independent of private Processing code and prepared JPEG inputs. It accepts only the supported ordinary one-primitive RGB base/normal/AO subset. Full1024–2048 textures and geometry remain unchanged; reduced512/256 images use exact centre sampling from that full, preserving role codes and optional sRGB intent. It does not qualify compact geometry, physical units or visual equivalence.

The request binds the existing idempotency key as operationID, a persisted generation and artworkRevision. Ready status includes the registered full/reduced asset IDs, actual SHA256/bytes and triangle/texture metrics. Optional derivation failure preserves the successful original import; stale/cancelled work cannot register a partial pair. Cancellation alone is not drain: callers poll `modelDerivation.workerDrained` before replacing an owned operation. CMS approval records a server-owned pair snapshot; publication independently rechecks current inventory, rights and actual pair correspondence. Existing original download and publication permissions remain separate.

A failed optional model derivative can use the existing retry action with the same persisted binding and still-current artwork revision. It reuses and rechecks the already approved original asset and bytes; it never uploads, re-encodes or re-registers that original. A completed pair is not regenerated. Existing attempt and current-rights limits still apply.
