# 함께 관람 개발 기능

공개 전시의 3D Viewer에서 `함께 관람 시작`을 선택하면 같은 공개 revision의 방문객을 아바타와 목록으로 표시한다. 기본값은 혼자 관람이며, 연결 실패·나가기·화면 숨김·상세 dialog 진입 시에도 전시 자체의 관람 기능을 유지한다. 오프라인 전시는 연결하지 않는다. 이 기능은 단일 API 프로세스의 개발 구현이며 다중 인스턴스 운영 배포를 지원한다고 주장하지 않는다.

## 권한과 개인정보

같은 origin의 `/api/v1/publications/<id>/presence` WebSocket을 사용한다. 공개 전시의 현재 권리와 공개 상태를 기존 서버 publication 검사를 통해 확인한 다음 입장을 허용한다. 클라이언트가 제출한 방문객 ID·이름은 허용하지 않는다. 서버가 임시 ID와 `Visitor` 이름을 발급한다. 공개 방문객에게 편집 권한을 부여하지 않는다.

입장과 연결 중 최대 2초 간격으로 공개 권리를 재검사하며 철회·revision 변경 시 방을 종료한다. 권리 철회 즉시 이미 수신한 전시 데이터가 브라우저에서 사라진다는 의미는 아니다. 위치·방·시선 회전은 명시적으로 함께 관람을 시작한 동안만 전송하며 대화·계정 이름·방문 이력은 수집하지 않는다. 위치는 일시적 프로세스 메모리 상태다.

재접속 토큰은 32바이트 난수로 발급하고 서버는 해시를 보관한다. 브라우저는 메모리에만 보관하며 UI·URL·localStorage·로그에 저장하지 않는다. 재접속마다 토큰을 교체하며 이전 토큰은 거부한다. 세션은 30분, 끊긴 방문객의 복귀 예약은 30초다. 사용자가 나가면 예약을 제거한다. 프로세스 재시작 후에는 새 방문객으로 입장한다.

## 프로토콜과 예산

공유 `studio-contract`의 version 1 closed JSON 메시지를 사용한다. join/pose/leave/ping 이외의 메시지와 임의 필드는 거부한다. 서버 snapshot이 identity·명단·위치를 결정한다. 한 방은 예약을 포함해 20명, 프로세스는 16방·200연결로 제한한다. 입장 전 제한된 연결은 존재할 수 있지만 공개 metadata나 명단을 받지 않는다.

클라이언트 위치 송신과 서버 snapshot은 최대 10Hz다. 입력은 2KiB, 출력 대기열은 기본 64KiB로 제한하고 압축을 사용하지 않는다. 원격 아바타는 100ms 보간하며 외삽하지 않는다. 동작 줄이기 설정에서는 즉시 위치를 반영한다. 원격 아바타는 작품 선택과 보행 충돌에 참여하지 않는다.

개발 Vite proxy는 같은 origin의 `/api` WebSocket upgrade를 전달한다. 별도 reverse proxy를 쓰는 운영자는 upgrade와 Origin/Host 보존이 필요하며 운영 TLS·proxy·WAN 검증은 별도다. 공개/오프라인 OES 계약은 변경하지 않는다.

## 검사와 제한

`npm run check`, `npm run test:e2e`, `DOCKER_BIN=<docker 경로> npm run test:realtime`을 실행한다. 마지막 명령은 새 격리 PostgreSQL fixture, 실제 WebSocket 방문객 20명과 독립 Chromium 두 context를 사용한다. 실제 결과는 검사가 끝난 후 결과 문서에 기록한다. 코드가 있다는 사실만으로 실제 브라우저 동기화·부하 검사가 통과했다고 판단하지 않는다.

실기기 접근성, Windows, 원격 네트워크, 운영 용량·다중 서버 분산은 별도 검증 대상이다. Git 백업에는 코드만 포함된다. 이 일시적 presence 상태는 백업·복원하지 않는다.
