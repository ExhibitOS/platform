# Hayes private disposition continuation (proposed)

This data contract is inactive. A live, authenticated Manager session must send a fresh `hayes-disposition-challenge` bound to its exact operation, native owner and runtime manifest. After its fixed transaction is known to have committed, Platform may send one canonical `hayes-disposition-committed` selector on that same channel: the exact binding, owner, runtime manifest, challenge, committed receipt ID and SHA-256. Neither frame is a release receipt. A timeout or ambiguous COMMIT never permits a second insert or a success notification. Reconciliation must independently query the exact attempt in the same owned database; a retry with newly generated asset or receipt IDs is not reconciliation.

Manager's read-only committed-state query must check physical PostgreSQL system identifier and database OID, tenant/workspace/principal and exact attempt/job/lease identifiers, receipt ID and canonical bytes/hash, native owner, runtime and worker manifests, native evidence and all retained READY attestation fields, exact stage ID/object key/output hash and byte count, source asset and display asset IDs, source hash/size and output hash/size, derivative linkage and receipt digest, artwork revision and selected display reference, and the current rights and revocation state. The job is intentionally `approved` after settlement: a predicate requiring `processing` is not a committed-state readback. The receipt must be decoded and compared to values from the independently held live session and the joined database rows; a notification alone is not proof.

Positive native release requires a separately specified, owner-fenced durable intent and completion around the actual release of the retained resources. Only an authenticated completion bound to the exact attempt, owner, evidence, database and challenge can be considered by inventory. A receipt, file transfer acknowledgement, EOF, process exit, or missing lock cannot establish release. Unresolved attempts keep inventory, backup and destructive cleanup fail-closed. No stopped diagnostic profile is assumed resumable.
