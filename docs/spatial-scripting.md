# 공간 스크립트 작성과 관람

Studio의 `Spatial Scripting` 편집기는 WHEN 이벤트, THEN 동작과 앞 동작 이후의
AFTER 정수 밀리초를 작성합니다. 규칙 추가 후 입력을 편집하고 **규칙 적용**을
실행하세요. 기존 로컬 CAS 저장·서버 ETag 저장을 따릅니다. 미적용 입력은
시뮬레이션에서 실행하지 않으며 잘못된 입력은 원본 문서를 바꾸지 않습니다.
규칙 이름은 작가의 식별자이고 공개·OEX 이동에서도 보존됩니다. 방·구역·배치·
조명·오디오 참조만 목적지의 ID로 바뀝니다.

시뮬레이션은 관람에 사용하는 동일한 `SpatialEvaluator`로 시계와 이벤트를
검사합니다. capability 스위치는 모의 허용/거부입니다. 실제 음성·장면·권리
검사를 대신하지 않습니다. 시간 이벤트는 시계 진행으로, 일반 이벤트는 이벤트
전달로 검사하세요. 실행 기록에서 예약·거부·취소·한도 중단을 확인합니다.

공개 Viewer는 글 목록으로 시작하며 스크립트를 자동 실행하지 않습니다.
3D 관람을 선택한 뒤 **스크립트 시작**을 눌러 현재 관람객에게만 실행합니다.
정지, Esc, 화면 숨김·창 포커스 해제, 상세 열기·관람 중단은 예약과 비동기
작업을 취소하고 조명·작품 표시를 원래대로 복원합니다. 다시 실행하려면
명시적으로 시작합니다. 작품을 숨겨도 보행 충돌과 원문 작품 목록은 유지합니다.
**전시 마침 동작 실행**은 exhibition_end 규칙을 전달하는 별도 버튼이며,
즉시 취소·복원하는 **스크립트 정지**와 역할이 다릅니다.

방·구역 입출입은 실제 camera 위치의 경계 변화입니다. 작품 접근은 차폐되지 않은
1.5m 범위, 바라보기는 차폐되지 않은10m·10도 범위에서500ms 머문 시점의 edge입니다.
작품 클릭과 선언된 사용자 이벤트는 선택 버튼으로도 전달할 수 있습니다.
강제 이동·서버 전역 변경·다른 관람객 상태 변경은 제공하지 않습니다.

오디오는 **소리 켜기**와 **스크립트 오디오 허용**이 모두 필요합니다.
기존 승인된 PCM WAV와 현재 공개 권리·해시·기기 예산을 검사합니다. 음성 또는
오디오 구역에 원문 대본을 연결하지 않은 script audio는 READY에서 거부합니다.
임의 URL·파일·네트워크·OS 호출과 JavaScript 실행은 지원하지 않습니다.
권리는 동작마다, 실행 중에는2초 간격으로 재확인하며 실패하면 취소·복원합니다.
글과 대본은 음성을 켜지 않아도 읽습니다.

프로그램은 optional `org.exhibitos.runtime/spatial-scripting`, version1입니다.
기존 OES의 비활성 `scripts`를 켜거나 변환하지 않습니다. 포함된 프로그램16KiB,
32규칙·규칙당16동작·최대1시간 정수 지연, 예약256·한 pump64·세션1024동작,
재귀8·trace128 한도를 적용합니다. 조명은 원래 밝기의0..1 배율이며500ms보다
빠른 연속 변경은 억제합니다. 숨기기와 밝기 변경도 기존 접근성 설정·읽기 목록을
유지하지만 새 UI의 실제 VoiceOver 검증은 별도 릴리스 조건입니다.

`npm run test:scripting`은 합성 PostgreSQL/production Chromium에서 편집·저장·
공개·실제 Three 조명/표시·취소와 승인 WAV 동의 검사를 실행합니다.
`npm run test:spatial-core`는 컴파일된 실행 코어의 ordering·재귀·권한·취소를
검사합니다. 소프트웨어 검사는 실제 청취·물리 기기 지원을 보장하지 않습니다.

프로그램은 전시 metadata의 일부입니다. Studio JSON은 metadata만 보관합니다.
OEX에는 승인된 원문 media를 함께 이동할 수 있으며 서버 서비스 복구는 일관된
DB와 blob 백업이 모두 필요합니다. 세션별 임시 예약·trace는 보존 대상이 아닙니다.
공개 Spec artifact를 이전 버전으로 되돌릴 때 optional namespace를 실행하지 않는
호환성을 유지하고 기존 DB나 원본 media를 삭제하지 마세요.
