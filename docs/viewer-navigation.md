# Viewer 보행 사용과 지원 범위

상태: 구현 후보. 실제 물리·키보드·터치 검사는 통과했으나 실제 마우스 캡처는 미검증입니다. [실행 결과와 남은 조건](performance/navigation-results.md)을 확인하세요. 최종 검증·병합 전에는 보행 단계 전체의 완료로 해석하지 않습니다. 기존 공개 전시 로딩과 권리 제한은 [Viewer 안내](viewer.md)를 따릅니다.

## 관람 조작

공개 전시는 정지 관람으로 시작합니다. `걷기 시작`을 선택하면 보행 엔진을 준비하고 안전한 위치에서 시작합니다. 웹 화면에 초점을 두고 W/A/S/D 또는 위·아래 화살표로 이동하고, 좌우 화살표로 시점을 돌립니다. 마우스로 시점을 돌리려면 `마우스 시점 잡기`를 직접 선택합니다. 브라우저가 마우스 캡처를 허용하지 않으면 키보드 조작과 정지 관람을 사용할 수 있습니다.

Esc, 다른 입력 항목으로 초점 이동, 창 초점 상실, 숨겨진 탭, 마우스 캡처 상실은 보행을 멈추고 눌린 입력을 해제합니다. 돌아온 뒤 `걷기 재개`를 선택합니다. 일시 정지와 재개는 현재 위치를 유지하며, `안전한 시작 위치로`는 시작 위치 복원을 명시적으로 요청합니다. `정지 관람으로 전환`으로 기존 관람 조작을 사용합니다. Studio 공간 편집의 orbit 미리보기는 별도로 유지합니다.

터치 화면에서는 왼쪽 이동 버튼과 오른쪽 화면 드래그를 함께 사용합니다. 이동과 시점 포인터는 각각 해제·취소할 수 있습니다. 터치 에뮬레이션 검사는 실제 iPhone/Android 장치의 성능·입력 검증을 대신하지 않습니다.

속도는 0.7/1.3/1.6 m/s 중 선택하며 기본은 1.3 m/s입니다. 가속과 감속을 적용하므로 정지 상태에서 바로 일정 속도가 되지 않습니다. 기본 눈높이는 1.65 m이며 1.2–1.7 m 사이로 조절합니다. 눈높이 조절은 몸의 충돌 크기를 줄이지 않습니다. OS의 움직임 줄이기 설정을 기본으로 반영하고 사용자가 변경할 수 있습니다. 강제 달리기·점프·머리 흔들림은 제공하지 않습니다.

## 공간과 충돌

미터 단위의 방·표면·작품 배치를 사용합니다. 서 있는 몸의 높이는 1.75 m, 반지름은 0.25 m입니다. 문과 창문은 실제 직사각형 구멍과 몸의 여유 공간으로 검사하므로 작은 창문을 문처럼 통과할 수 없습니다. 작품 데이터가 아직 로딩되지 않아도 공개 배치의 치수·회전 bounds는 충돌 장애물로 남습니다. 카메라 시작점이 위험하면 검사한 안전 위치를 찾거나 보행 초기화를 거부합니다.

구현 후보의 제한은 최대 25 cm 단차, 30 cm 착지 폭과 35° 오르막입니다. 위·아래 단차와 경사, 머리 공간·바닥 끝은 실제 물리 검사로 확인해야 하며 모든 계단·곡면 공간의 지원을 뜻하지 않습니다. 바닥의 문/창문 구멍은 현재 보행 프로필에서 지원하지 않습니다. 지원하지 않는 변환·복잡도·공간은 보행을 거부하며 정지 관람과 목록을 유지합니다.

내부 보행 영역은 삼각형 셀과 인접 그래프로 구성합니다. 처음 25 cm 그리드를 사용하고 후보 셀이 4,096개를 넘으면 간격을 넓힙니다. 셀의 중심·모서리·몸의 여유 공간과 연결 구간을 물리 검사합니다. 보수적인 셀 검사 때문에 실제 통과 가능한 좁은 경로도 그래프에서 제외될 수 있습니다. 이 런타임 artifact는 OES/OEX에 저장되는 규격이나 관람객 자동 이동 기능이 아닙니다.

방 32개, 표면 256개, 구멍 128개, 작품 배치 128개, collider 8,192개와 그래프 연결 32,768개를 상한으로 둡니다. 시뮬레이션은 60 Hz로 진행하며 한 프레임에서 최대 250 ms/15개 단계를 처리합니다. 더 긴 프레임 정지는 초과 시간을 버리므로 실제 경과 시간과 이동 거리가 같다고 보장하지 않습니다. 이 제한은 긴 정지 뒤 갑자기 큰 거리를 이동하는 것을 막습니다.

## 검증과 한계

검사 조건과 필수 증거는 [보행 검증 절차](performance/navigation-protocol.md), 기술 선택은 [ADR 0010](adr/0010-viewer-first-person-collision.md)에 있습니다. 실제 실행 결과는 최종 후보에 대해 별도로 기록해야 합니다. Rapier 0.21.0의 원래 Apache-2.0 고지는 production의 THIRD_PARTY_NOTICES.txt에 포함합니다.

마우스 캡처의 실제 성공과 DOM 이벤트 주입 검사는 구분합니다. Headless 브라우저 제한을 실제 장치 지원 실패나 성공으로 일반화하지 않습니다. 물리 모바일 장치·GPU·탭 전체 메모리와 일반 임의 공간은 아직 검증하지 않았습니다. 보행은 작품 접근 권한을 바꾸지 않으며 비공개 원본 다운로드 권한을 제공하지 않습니다.
